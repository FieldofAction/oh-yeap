# Working in this repository

The site is fieldofaction.org: a Vite + React app (`src/`), static experiment
pages generated by `scripts/experiments-build.mjs`, and a shared typography
layer in `src/styles/field-standard.css`. `npm run build` runs the typography
tests first; `node scripts/text-rule-test.mjs` runs the page-text rule below
against a built preview. Everything in `scripts/fixtures/` is checked in on
purpose.

## TEXT ON THE PAGE — the rule

Every piece of text does one of three jobs: it says the idea, it names
the thing, or it operates a control. If a line does none of these, it
does not exist. Test: delete it. If the reader loses nothing they
would act on or need to understand the next line, it stays deleted.

There are two levels of text: the headline and the body. Beneath them,
only functional text — a form label, a nav link, a caption that
identifies an image, a date. Nothing is added to make the page look
designed, considered, or complex.

Do not add, anywhere, unprompted:
- labels above a headline (eyebrow, kicker, overline, category word)
- taglines or descriptors under a title ("Generative · Field of Action")
- path or breadcrumb labels as decoration (A / B / C, SECTION / PAGE)
- numbered section labels (01 — NAME)
- status or state lines ("Working interpretation", "Open to revision",
  "Research in progress", "Hypothesis · updates with your choices")
- counts and stats as ornament ("53 observations / 38 source pages")
- small uppercase tracked text of any kind
- monospace for labels or meta (mono is for code and indices only)
- arrows on links (↗ → ←); the underline is the affordance
- a second line of small text explaining what the first line meant

If a page seems to need a label to be understood, the headline is
wrong: fix the headline. If a section has only a label for a title,
give it a real heading or merge it into its neighbour.

When editing an existing page, remove what fails this rule; do not
restyle it. Delete the CSS, don't hide the element. Report what was
removed and why.

## How the checks enforce it

The function rule above is authoritative. Automation catches recurring concrete
patterns; a passing check does not establish whether a sentence is useful.
Review the rendered page and apply the deletion test to text that heuristics miss.

`npm run build` runs the existing typography tests, the static text guard and the
baseline helper tests before generating experiments and bundling the public app.
`CLAUDE.md` is an input to those tests, so `.vercelignore` explicitly includes it.
The separate `build:studio` script does not run the public `prebuild` hook.

`scripts/text-on-the-page-test.mjs` checks public source for label-named classes,
known labels above headings, literal arrows in simple links/buttons, and new CSS
rules combining uppercase with a literal font size below 12px. PublicSidebar is
covered; the deprecated Philosophy component is excluded (Canon owns that route).
Its existing `scripts/text-on-the-page-baseline.json` is legacy CSS debt, not
permission to add decorative text. Builds never create or rewrite this baseline.
Retire entries explicitly in review when their CSS is removed.

`npm run text:test` inspects ten built-page scenarios (including the open navigation menu) at mobile/desktop widths in
both themes. It checks computed small text (12px or smaller) immediately before
an h1–h3, computed small uppercase, mono labels outside code/indices/form fields,
and arrow text inside links/buttons. It records every occurrence, so another
link with the same classes cannot borrow an existing link's allowance. The audit scrolls through content to activate normal reveal behavior. Hidden
text is not rendered evidence. Do not hide violations to satisfy the audit.

The browser baseline `scripts/fixtures/text-rule-baseline.json` is an empty array:
no browser findings are grandfathered. The first CI audit at `ce9a66e` inspected
36 scenarios and found 996 occurrences (572 mono, 424 small uppercase). Review
removed redundant hero and navigation labels, the experiment-index descriptor
and count, and duplicated experiment masthead metadata. Dates, controls,
research confidence/provenance, tags, and actual headings remain functional;
their mono/uppercase treatment was removed. Heading names are now real h2s.
Existing numbered indices and experiment identifiers alone carry `data-mono`.
Only cased letters can trigger the uppercase check; symbols still undergo the
arrow check. The empty baseline passes only when the actual audit finds zero
violations. Neither builds nor `npm run text:baseline` can bootstrap allowances.

`npm run text:baseline` only retires entries from an existing baseline and refuses
new findings. On PRs, `scripts/text-rule-baseline-test.mjs` also compares committed
allowances against the base commit: inherited baselines cannot grow or disappear.
The first introduction of an allowance list still needs human review. Never add
`data-mono` to silence a label; it is only for genuine code or index content.
Existing case-study § numbers, Materials study legends, and tags/chips that name
or operate something remain functional. None is a blanket decoration exemption.

The GitHub workflow runs on PRs to main. Browser fixtures, typography review and
text inspection run independently after a successful build; one failing review
does not suppress another. The audit writes a report even when browser startup
or a route fails, and failed/incomplete runs cannot rewrite a baseline.

## Coverage limits

Source regular expressions do not parse arbitrary JSX or the CSS cascade.
The browser check observes only visited routes/states; its text-node heuristics
do not catch every nested label, pseudo-element, icon or unhelpful sentence.
Keep the small fixture suite for known failure modes and extend route/state
coverage when a public template changes. Avoid adding broad exceptions or
refreshing baselines wholesale. Neither tool replaces editorial judgment.
