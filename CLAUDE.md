# Working in this repository

The site is fieldofaction.org: a Vite + React app (`src/`), static experiment
pages generated by `scripts/experiments-build.mjs`, and a shared typography
layer in `src/styles/field-standard.css`. `npm run build` runs the typography
tests first; `node scripts/text-rule-test.mjs` runs the page-text rule below
against a built preview. Everything in `scripts/fixtures/` is checked in on
purpose.

## TEXT ON THE PAGE — the rule

Every piece of text does one of three jobs: it says the idea, it names
the thing, or it operates a control. If a line does none of these, it
does not exist. Test: delete it. If the reader loses nothing they
would act on or need to understand the next line, it stays deleted.

There are two levels of text: the headline and the body. Beneath them,
only functional text — a form label, a nav link, a caption that
identifies an image, a date. Nothing is added to make the page look
designed, considered, or complex.

Do not add, anywhere, unprompted:
- labels above a headline (eyebrow, kicker, overline, category word)
- taglines or descriptors under a title ("Generative · Field of Action")
- path or breadcrumb labels as decoration (A / B / C, SECTION / PAGE)
- numbered section labels (01 — NAME)
- status or state lines ("Working interpretation", "Open to revision",
  "Research in progress", "Hypothesis · updates with your choices")
- counts and stats as ornament ("53 observations / 38 source pages")
- small uppercase tracked text of any kind
- monospace for labels or meta (mono is for code and indices only)
- arrows on links (↗ → ←); the underline is the affordance
- a second line of small text explaining what the first line meant

If a page seems to need a label to be understood, the headline is
wrong: fix the headline. If a section has only a label for a title,
give it a real heading or merge it into its neighbour.

When editing an existing page, remove what fails this rule; do not
restyle it. Delete the CSS, don't hide the element. Report what was
removed and why.

## How the build enforces it

`scripts/text-rule-test.mjs` opens the built pages in a headless browser and
flags: text at 12px or smaller immediately before an h1–h3; uppercase text at
12px or smaller; a monospace face outside `code`, `pre`, `kbd`, `samp`, form
fields and elements marked `data-mono`; and ↗ → ← inside a link or button.
Findings are compared with `scripts/fixtures/text-rule-baseline.json`. A
finding that is not in the baseline fails the run. The baseline only shrinks:
when you remove a violation, run `npm run text:baseline` and commit the smaller
file. Do not add entries to the baseline by hand, and do not mark an element
`data-mono` to silence the check unless it is genuinely an index or code.
